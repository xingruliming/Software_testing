================================================================================
缺陷复现记录  DEF-M2-003
低置信场景下置信度过滤（--conf-thres）静默失效，实际过滤率与参数语义严重不符
================================================================================

【被测软件】  VGGT（vggt-main 基线）
【缺陷编号】  DEF-M2-003
【严重程度】  中 / 优先级 高 / 状态：已确认，待修复
【测试时间】  2026-09-13
【关联用例】  M2-AI-010；新增 M2-AI-016

--------------------------------------------------------------------------------
1. 缺陷定位
--------------------------------------------------------------------------------
文件：vggt-main/visual_util.py
函数：predictions_to_glb
代码段（置信度过滤）：

    conf = pred_world_points_conf.reshape(-1)
    if conf_thres == 0.0:
        conf_threshold = 0.0
    else:
        conf_threshold = np.percentile(conf, conf_thres)
    conf_mask = (conf >= conf_threshold) & (conf > 1e-5)

函数文档对 conf_thres 的说明是：
    "Percentage of low-confidence points to filter out (default: 50.0)"

--------------------------------------------------------------------------------
2. 缺陷机理
--------------------------------------------------------------------------------
判据用的是**百分位**而不是绝对阈值。而模型对「无置信」像素输出的置信度存在
**地板值 1.0**（即它没有把握时也输出 1.0，而不是 0 或负数）。

当多数像素压在地板值上时：
    median(conf) == 1.0
    => conf_threshold == 1.0
    => (conf >= 1.0) 对**全部像素成立**
    => 实际过滤率 0%，而非参数声称的 50%

全过程没有任何日志或警告，使用者无法从输出判断过滤是否生效。

--------------------------------------------------------------------------------
3. 复现步骤与实测结果
--------------------------------------------------------------------------------
方法：读取各场景的 predictions.npz，统计置信度等于地板值 1.0 的像素占比、
      中位数，以及按上述判据计算的实际保留率。

场景                        置信度   等于 1.0 占比   中位数      实际保留率
--------------------------  --------  -------------  ----------  --------------
002_computer（对照，正常）  depth    9.5%           9.33        50.00%  正常
006_meal                    depth    —              1.0001      50.00%  临界侥幸生效
005_football                depth    64.7%          1.0000      100.00% 失效
004_feiji                   depth    84.7%          1.0          100.00% 失效
009_arbus N32               wp_conf  86.4%          1.000000     100.00% 失效

详细数值：

* 009_arbus N32（最极端）
    world_points_conf 中位数 = 1.000000，86.4% 的像素等于 1.0
    => conf >= percentile(conf, 50) 保留 8,586,368 / 8,586,368 点 = 100.00%
    即导出的 GLB 包含**全部像素**，一个点都没有被过滤掉。

* 005_football（10 帧近景足球）
    depth_conf 中位数恰为 1.0，64.7% 的像素等于 1.0
    => Depthmap 分支保留 2,030,560 点 = 100.00%
    （同场景 world_points_conf 中位数 1.0735，保留率 50.00%，故 Pointmap 分支反而正常）

* 004_feiji（3 帧客机模型）
    depth_conf 有 84.7% 的像素恰好等于 1.0 => 保留 609,168 点 = 100.00%

* 006_meal（9 帧汤碗）
    depth_conf 中位数 1.0001，仅比地板值高 0.0001
    => 保留率 50.00%，属**临界侥幸生效**（阈值或场景稍变即会失效）

* 002_computer（对照，9 帧教室场景）
    仅 9.5% 等于 1.0，中位数 9.33 => 正常筛到 50.00%

--------------------------------------------------------------------------------
4. 影响
--------------------------------------------------------------------------------
* 默认参数（50.0）是最常被使用的路径，使用者极易误以为导出结果已经过置信度筛选。
* 低置信场景下过滤完全失效，低质量点与背景点全量进入 GLB：
  这是 DEF-M2-004（背景被一并重建）中「原始导出含全部背景」的直接原因。
* 该问题在 4 个独立场景上复现，属系统性问题而非个例。

--------------------------------------------------------------------------------
5. 修复建议
--------------------------------------------------------------------------------
1) 低置信场景改用**绝对阈值**（如 conf >= 3.0），而不是百分位；
2) 当检测到实际过滤率显著偏离 (1 - conf_thres%) 时打印告警，
   例如「置信度大量集中于地板值 1.0，百分位过滤已失效，建议改用绝对阈值」；
3) 把等于地板值的像素显式视为「无置信」并单独处理，而不是当作有效的中等置信。
