缺陷复现记录  DEF-M2-005
OpenCV 在非 ASCII（中文）路径下静默写失败，且 imwrite 返回值不可信
================================================================================

【被测软件】  VGGT（vggt-main 基线）
【缺陷编号】  DEF-M2-005
【严重程度】  中 / 优先级 中 / 状态：已确认，工程内已提供规避方案
【测试时间】  2026-09-13
【关联用例】  新增 M2-AI-018
【实测环境】  opencv-python 4.13.0（Pytorch_Vggt 环境）

--------------------------------------------------------------------------------
1. 缺陷定位
--------------------------------------------------------------------------------
根因在 OpenCV 本身：cv2.imwrite / cv2.imread 内部按本地编码解释路径，
遇到非 ASCII 字符即失败。

基线中受影响的调用点：
* demo_gradio_cn.py  —— save_depth_images() 保存深度图、视频抽帧保存帧
* visual_util.py     —— segment_sky() 读图与写掩码
* vggt/utils/visual_track.py
* demo_gradio.py / demo_viser.py

--------------------------------------------------------------------------------
2. 缺陷机理与严重性
--------------------------------------------------------------------------------
不只是「失败」，而是**失败得没有痕迹**：

  cv2.imwrite 在中文文件名下**返回 True，但文件根本没有写出**。

因此调用方无法通过返回值发现失败：没有异常、没有 False、日志里也看不到错误，
最终表现为「产物目录是空的」或「深度图数量不对」。
这类「返回值与实际行为不符」的静默失败比直接抛异常危险得多。

--------------------------------------------------------------------------------
3. 复现步骤与实测结果
--------------------------------------------------------------------------------
步骤 1：构造四种路径组合，分别调用 cv2.imwrite，
        记录返回值并检查文件是否真实存在（重复 5 次）。

路径情形                  imwrite 返回   文件是否真的写出    cv2.imread 能否读回
----------------------  ------------  ----------------  ------------------
ASCII目录/ASCII文件名      True          True              能
中文目录/ASCII文件名         False         False             不能（返回 None）
ASCII目录/中文文件名         False/True*   False             不能（返回 None）
中文目录/中文文件名          False         False             不能（返回 None）

    * 在中文文件名情形下多次实测返回值不稳定：既有 False，
      也有连续 5 次均返回 True 而文件**不存在**的情况
      （实测片段：imwrite 返回 True，文件存在 False，连续 5 次一致）。
      即**返回值本身不可信**，不能作为成功判据。

步骤 2：隔离测试 cv2.imread —— 先用 open() 保证文件真实存在，再读。
        ASCII目录/ASCII文件名  -> OK
        其余三种含中文的路径    -> 全部返回 None（失败）

步骤 3：改用 Unicode 安全写法复测同样四条路径：
        写：cv2.imencode(ext, img)[1].tobytes() 配合 open(path, "wb").write(...)
        读：cv2.imdecode(np.fromfile(path, np.uint8), cv2.IMREAD_COLOR)
        结果：四条路径**全部成功**（写入正常、读回正常）。

--------------------------------------------------------------------------------
4. 与前序记录的关系（重要）
--------------------------------------------------------------------------------
本工程的工作副本路径已改为纯 ASCII（E:\0_work\1shijian\Software_testing），
因此该缺陷**不会再被仓库路径自动触发**，必须人为构造含中文的目录或文件名
才能复现。这一点在做缺陷验证与回归时必须注意，否则会误判为「已修复」。

--------------------------------------------------------------------------------
5. 修复建议
--------------------------------------------------------------------------------
1) 把所有图像读写点统一替换为 Unicode 安全实现（imencode / imdecode）；
2) 或直接套用本工程已有的兼容层 cv2_unicode.py：
       import cv2_unicode
       cv2_unicode.patch()      # 之后原 cv2.imread / cv2.imwrite 自动支持中文路径
   —— 它替换的是 cv2 模块属性，运行时按名查找，**不需要改动任何调用点**；
       cv2_unicode.unpatch() 可还原，便于缺陷复现。
3) 无论采用哪种方案，都不应把 cv2.imwrite 的返回值当作写入成功的判据。
