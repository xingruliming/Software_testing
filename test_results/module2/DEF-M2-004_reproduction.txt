================================================================================
缺陷复现记录  DEF-M2-004
输出未区分目标与背景；内置背景剔除仅支持颜色阈值，无法处理抗锯齿边缘
================================================================================

【被测软件】  VGGT（vggt-main 基线）
【缺陷编号】  DEF-M2-004
【严重程度】  低（工程内已有替代方案） / 优先级 中 / 状态：已确认，建议改进
【测试时间】  2026-09-13
【关联用例】  新增 M2-AI-017

--------------------------------------------------------------------------------
1. 缺陷定位
--------------------------------------------------------------------------------
文件：vggt-main/visual_util.py
函数：predictions_to_glb
相关参数：mask_white_bg / mask_black_bg（颜色阈值背景剔除）

    if mask_white_bg:
        white_bg_mask = ~((colors_rgb[:, 0] > 240) & (colors_rgb[:, 1] > 240)
                          & (colors_rgb[:, 2] > 240))
        conf_mask = conf_mask & white_bg_mask

即内置的背景剔除只有「RGB 三通道全部 > 240 判为白底」与「黑底」两种颜色阈值，
**没有提供传入自定义掩码的接口**。

--------------------------------------------------------------------------------
2. 缺陷机理
--------------------------------------------------------------------------------
VGGT 对每一帧的**每个像素**都回归一个世界坐标，它不区分「这是物体」还是
「这是背景」。在纯白背景的渲染数据集上（009_arbus，白色像素占 91%~96%），
导出的点云里绝大多数点其实是背景平面。

而抗锯齿边缘像素是**目标与白底的混合色**（介于两者之间），颜色阈值法在原理上
无法将其与目标区分，必然残留一圈薄壳。

--------------------------------------------------------------------------------
3. 复现步骤与实测结果
--------------------------------------------------------------------------------
数据：009_arbus 的 N32（32 帧，预处理后 518×518，共 8,586,368 像素）

方案 A：默认导出（不启用任何背景过滤）
    保留 8,586,368 点（100.00%）
    其中落在目标之外的点数（残留背景）：8,097,193，占保留点 94.30%
    包围盒对角线 2.210  ← 背景把尺度撑大

    （说明：该场景百分位过滤本身也失效，见 DEF-M2-003，因此这里是全量输出）

方案 B：--mask-white-bg（内置颜色阈值）
    保留 569,121 点（6.63%）
    其中落在目标之外的点数：79,958，占保留点 14.05%   ← 残留
    包围盒对角线 0.687

方案 C：GT 掩码 + 腐蚀 1px（工程内替代方案）
    保留 489,175 点（5.70%）
    其中落在目标之外的点数：0
    包围盒对角线 0.678

对比 A 与 C：目标真实占比仅 5.70%，而包围盒对角线从 2.210 收敛到 0.678
（缩小 3.3 倍），可见背景对结果的影响之大。
对比 B 与 C：包围盒只差 1.3%，说明 B 的残留是**贴着轮廓的一层薄壳**，不是大平面。

--------------------------------------------------------------------------------
4. 阈值扫描：内置的 240 已是最优，没有可调空间
--------------------------------------------------------------------------------
阈值      背景删除率    目标误删率
---------  ------------  ------------
190        99.53%        45.27%
210        99.36%        25.96%
230        99.11%        7.40%
240        99.01%        0.00%      ← 内置默认值
250        98.90%        0.00%

结论：降到 230 只多删 0.1% 的背景，却要牺牲 7.4% 的目标；降到 210 会误删
近四分之一的目标。**240 已经是纯颜色法的最优点**，剩下约 1% 的背景像素
（≈79,958 点）是抗锯齿混合色，颜色法在信息上就无法分离。
=> 想彻底干净只能用掩码。

--------------------------------------------------------------------------------
5. 影响与能力边界
--------------------------------------------------------------------------------
* 若使用者只想要目标物体的点云，默认导出结果基本不可用（背景占 94%）。
* 内置的两种颜色阈值开关可缓解，但无法彻底解决，且文档未说明这一能力边界。
* 属「功能不足」类缺陷，不是推理错误——VGGT 的位置估计本身是正确的
  （该数据集上相对旋转误差 0.38~0.59°，见自检脚本与 DEF 报告中 3.4.6）。

--------------------------------------------------------------------------------
6. 工程内替代方案（本组已实现）
--------------------------------------------------------------------------------
tools/mask_pointcloud_export.py
    思路：把掩码外的 world_points_conf 与 depth_conf **置 0**，再以
          conf_thres=0.0 调用 predictions_to_glb。该函数对 conf_thres == 0.0
          有专门分支，且 conf > 1e-5 会把置 0 的点全部排除，
          于是掩码成为唯一过滤器，**无需修改基线代码**。
    用法：
        python tools/mask_pointcloud_export.py \
            --npz <predictions.npz> \
            --masks-dir vggt_input/009_arbus/masks \
            --selection <selection.json> \
            --out-dir <out> --mode gt --erode-px 1
    实测：N32 保留 489,175 点，残留背景 0。

--------------------------------------------------------------------------------
7. 修复建议
--------------------------------------------------------------------------------
1) 增加 mask_dir 参数以接收逐帧掩码，或在导出接口中支持传入掩码数组；
2) 在文档中明确说明背景剔除的能力边界（仅支持纯色背景、无法处理抗锯齿边缘）；
3) 可选：提供「按掩码裁剪点云」的正式后处理接口。
