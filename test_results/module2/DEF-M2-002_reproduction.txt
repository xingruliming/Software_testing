二、测试需求
------------
预处理应保持输入图像的完整视野；若发生裁切，应给出明确告警并在产物元信息中
记录有效区域范围，使输出深度图与点云同输入视野的对应关系可追溯。

三、复现步骤与结果
------------------
1. 准备竖构图图像序列 vggt_input/001_watercup（8 张，3072×4096，宽高比 0.75）。
2. 执行：
   D:\anaconda3\envs\Pytorch_Vggt\python.exe run_vggt_inference.py \
       --input-dir  vggt_input/001_watercup \
       --output-dir vggt_output/001_watercup
3. 观察日志：「预处理后张量形状: (8, 3, 518, 518)」——与输入 3:4 的宽高比不符。
4. 查阅 vggt_output/001_watercup/run_info.json：只有 image_shape 与 depth_shape，
   没有任何裁切标注或有效区域范围记录。
5. 实际结果：程序未打印任何告警，观察不到裁切行为。

四、裁切量核算
--------------
crop 分支逻辑（load_fn.py）：
  new_width  = 518
  new_height = round(height * (518 / width) / 14) * 14
  若 new_height > 518，则从 start_y = (new_height - 518) // 2 处中心裁切到 518 高

代入本场景：
  new_height = round(4096 * (518 / 3072) / 14) * 14 = round(49.33) * 14 = 49 * 14 = 686
  686 > 518 -> 纵向中心裁切
  纵向保留比例 = 518 / 686 = 75.5%，即丢弃 24.5%（上下各约 12.2%）
  按原始分辨率折算，每帧上下合计约 1024 行像素从未进入模型。

五、控制变量对照实验（定位成因）
--------------------------------
为避免把「裁切」误判为质量退化主因，做了一次对照：
  变体 sq001：把同一批 8 张图像居中补白成 4096×4096，使 crop 分支不再触发
              （new_height = round(518 / 14) * 14 = 518，无裁切），其余参数不变。
  结果对比（conf_thres = 1.0，均为 8 帧）：

    指标              原图（裁切 24.5%）   补白（不裁切）
    G1 相对误差        2.973e-2             3.629e-2
    G2 像素误差        41.447 px            39.237 px
    G4 NCC             0.4919               0.6465
    G3 置信均值        1.118                1.051

  结论：指标没有改善，置信度甚至略降。说明近景场景的质量退化主要由场景本身
  （近景、低纹理、小基线）导致，预处理裁切不是主因。
  因此本缺陷定性为「静默信息丢失」，而不是导致精度下降的性能缺陷。

六、预期结果
------------
默认应使用 pad 模式保持完整视野；若沿用 crop 模式，应打印「已裁切约 xx% 纵向视野」
的告警，并在 run_info.json 中记录有效区域范围。

七、修复建议（非处理结果）
--------------------------
1. 默认改用 pad 模式（load_and_preprocess_images 已支持 mode="pad"）；
2. 若必须沿用 crop，则在发生裁切时打印明确告警，并把有效区域（start_y、保留高度）
   写入 run_info.json 与预测结果元信息；
3. 说明文档中补充注明 crop 模式对非 1:1 输入会丢失视野。
