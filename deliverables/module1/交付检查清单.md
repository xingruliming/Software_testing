# 模块一提交前检查清单

## 仓库与运行

- [ ] 仓库根 README 能让新成员完成环境配置和运行。
- [ ] 每位成员使用个人账号提交真实工作，提交信息清楚。
- [ ] 没有一次性代提交、伪造作者或重写历史。
- [ ] `vggt-main` 没有与缺陷修复无关的改动。
- [ ] `model.pt`、GLB、点云、缓存、本地证书和 IDE 文件未进入新提交。
- [ ] `run_vggt_demo.ps1` 能启动原 `demo_gradio_cn.py`。
- [ ] 已人工完成一次页面、重建、三维显示、深度图和输出归档确认。

## 测试用例与自动化

- [ ] 附录1中有效用例不少于 30 条。
- [ ] 自动化用例不少于 24 条，且一键入口能运行全部自动化用例。
- [ ] 至少采用等价类、边界值、场景法中的两种方法。
- [ ] 每条用例的编号、输入、步骤和预期结果清楚且可判定。
- [ ] 实际结果和状态来自真实执行，不是预填或模拟。
- [ ] 用例编号与测试代码、日志、缺陷编号可追溯。

## 执行结果与缺陷

- [ ] 已保存完整终端日志和 JUnit XML。
- [ ] Excel、日志和报告的用例总数、通过数、失败数及通过率一致。
- [ ] 至少 3 个缺陷经过真实复现，并具有日志或截图证据。
- [ ] 每个缺陷包含环境、步骤、预期/实际结果、严重程度、处理方案和复测结果。
- [ ] 没有把环境错误、用例错误或重复现象拆分成多个缺陷。

## 报告与汇报

- [ ] 测试报告按附录3填写完整，建议不超过 2000 字。
- [ ] 报告包含 5–8 个典型用例和 2–3 个典型缺陷根因分析。
- [ ] 质量结论由真实测试证据支撑。
- [ ] 成员贡献度合计 100%，并与 Git 提交和实际工作一致。
- [ ] PPT 为 10–12 页、讲解 5–8 分钟，不直接复制报告。
- [ ] 演示视频包含核心功能、一键测试、执行结果和典型缺陷。
- [ ] 文档、截图和视频未泄露密码、令牌或其他敏感信息。
