# 模块一测试工作汇报 · 版式说明

本 PPT **直接以 `E:\0_work\PPT模版\华科蓝.pptx` 为底板**制作：保留模板自带的母版、主题、
图形组合、校徽、校园照片与配色，**只改写每页的 `<a:t>` 运行文本**。因此视觉与模板完全一致。

构建方式：**包级手术**（解包 pptx → 定位形状 → 替换文本 → 重新打包），
不使用 `slidep` DSL。原因：`slidep create` 没有套模板选项，`upsert-dsl` 会整页替换、
丢掉模板每页自带的图形组合（R 标、深蓝圆形、校徽、校园照片、交替色卡）；
本地 SDK 的 `slide_find_replace_text` 又不遍历组合形状（grpSp），而模板文字几乎全在组合里。

构建脚本：`tools/_rebuild_deck.py`（可重复执行，替换函数内置 XML 实体转义）；
校验脚本：`tools/_verify_pptx.py`；渲染脚本：`tools/_export_png.ps1`（PowerPoint COM）。

## 已核对的排版问题（均已修正）

- **XML 实体未转义**：新副标 `TEST OBJECT & CORE FUNCTIONS` 的 `&` 直接写入 `<a:t>`
  → slide3/slide4 XML 非法（校验器抓到，PowerPoint 会拒开）→ 替换函数统一转义
  `& → &amp;`、`< → &lt;`、`> → &gt;`。
- **P04 行标题折行**：「核心功能：坐标转换链」10 字、「测试要点：绝对位姿不可比」12 字
  → 缩为「核心功能链」「绝对位姿不可比」。
- **P10 正文压行**：第 1 行正文 3 行压住第 2 行标题 → 删括号补注压回 2 行。
- **P02 目录折行**：8~9 字条目全部折两行 → 条目缩为 ≤5 字（被测对象/测试策略/自动化实施/结果与结论）。
- **P07 卡片标题溢出**：「错误推测（加固）」8 字 → 四卡标题 ≤5 字。
- **P01 标签行折行**：`2 种核心方法` 比 `2 种方法` 长 2 字即折行 → 定稿 11 字。
- **P01/P12 汇报人行折行**：`2026年9月` → 紧凑 `2026.9`。
- **P08 三行内容溢出**：用例号列表过长 → 条数移到副标 `EQUIVALENCE · 19 CASES`。
- **形状定位一律按 id**：模板 XML 书写顺序 ≠ 视觉顺序（slide 8 四卡为 `26/11/13/40`）。
- **同一文件禁止并行多个 Edit**：后写覆盖先写，两条都报 success（v5 实际翻车）。

## 内容口径（与排版同等重要）

1. **方法名与条数必须与 `VGGT模块一测试用例清单.xlsx` 备注列逐字一致**：
   等价类 19 / 边界值 5 / 组合覆盖 4 / 错误推测 2 / 判定表 2（共 32 条）。**无场景法**。
2. **代码行号以源码为准**：L15 unproject / L22 docstring / L39 squeeze 根因 /
   L47 depth_to_world / L87 depth_to_cam / L98 `H, W` 解包报错点
   （勿再用旧稿的 L38/71/98）。
3. 33 = 32 条清单用例 + 1 条绕障对照（清单外），故清单 OK 率 93.75%、执行通过率 93.9%。
4. **geometry.py 是 NumPy/PyTorch 混合实现**（第 8 行 `import torch`，约半数函数为
   torch 实现）——**不得写「纯 NumPy」**（用户指出过此错误，v13 修正）。
5. **VGGT 官方事实**（论文 / HF `facebook/VGGT-1B` / vgg-t.github.io）：Meta AI + 牛津
   VGG、CVPR 2025 最佳论文；前馈式网络，单次前向从 1~数百张图像预测相机内外参、
   深度图、点图、3D 点轨迹；约 10 亿参数（VGGT-1B）。技术性论断先对源码/文献核实。

## 复制页面的强制要求（否则 PowerPoint 拒开）

1. **每个复制页必须有自己的 `ppt/tags/tagN.xml` 部件**（tag 只能属于一个幻灯片）。
2. **`presentation.xml.rels` 旧 slide 关系按 `Type` 属性剔除**
   （Target 无前导斜杠，字符串过滤会漏）。
3. **`[Content_Types].xml` 为磁盘上实际存在的所有 tag 声明 Override**。
