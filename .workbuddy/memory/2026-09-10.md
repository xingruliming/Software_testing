## 【根治】Windows asyncio ConnectionResetError 刷屏

- 现象（用户反复遇到）：浏览器刷新/关闭页面就打印
  `Exception in callback _ProactorBasePipeTransport._call_connection_lost(None)`
  `ConnectionResetError: [WinError 10054] 远程主机强迫关闭了一个现有的连接。`
- 根因：环境为 **Python 3.10.20**，`asyncio/proactor_events.py` **第 165 行**
  `_ProactorBasePipeTransport._call_connection_lost` 的 `finally` 块里调用
  `self._sock.shutdown(socket.SHUT_RDWR)` 抛错。因该回调由 `loop.call_soon` 调度，
  asyncio 视作未处理异常打印。CPython 已知问题 **gh-93823**
- **额外损害**（不只刷屏）：异常抛在 `finally` 中，导致后面的
  `_sock.close()`、`_sock = None`、`server._detach()`、`_called_connection_lost = True`
  **全部被跳过**，transport 处于半清理状态
- 修复：`demo_gradio_cn.py` 新增 `_patch_windows_asyncio_connection_reset()` 并在模块导入后立即调用
  - 仅 `sys.platform == "win32"` 时生效
  - 包一层 `_call_connection_lost`：捕获 `ConnectionResetError` 后**补完上述清理**并返回 None
  - 其他异常（如 RuntimeError）仍照原样抛出；补丁失败只打印提示不影响运行
- 验证（`D:\Anaconda3\envs\Pytorch_Vggt`）：用 AST 抽取真实补丁源码跑两组测试
  - 桩对象：确认原方法确实抛错且 `_called_connection_lost` 仍为 False（证明清理被跳过）；打补丁后不抛错、`_sock` 置空、`server._detach()` 被调用、`_called_connection_lost=True`；RuntimeError 仍正常抛出
  - 真实 ProactorEventLoop：正常 TCP 收发不受影响（收到 b'hello'），SO_LINGER 强制 RST 后事件循环捕获的 ConnectionResetError 为 0

### ⚠️ 重要更正：环闭合检验对 VGGT 恒等于单位阵
我上一轮建议的「位姿环闭合 T_AB·T_BC·T_CA ≈ I」是**错的**。推导：
`T_{C→A}·T_{B→C}·T_{A→B} = (T_A T_C⁻¹)(T_C T_B⁻¹)(T_B T_A⁻¹) = I`，中间项两两抵消，
**与位姿取值无关**，残差只有浮点误差 ~1e-7。因为 VGGT 一帧一次前馈，所有位姿同源于一次预测、天然互相自洽。
传统 SfM 每对相对位姿独立估计，所以环合才有效。
→ 已用 **G5 分段一致性（窗口一致性）** 替代：用不同帧窗口各跑一次，比较重叠帧的**相对**位姿。
文档附录 B 有完整推导。
